Diagnóstico y arreglo de TLS

Equipos Windows · Diagnosticar-TLS.ps1 · versión 1.0
«No se puede crear un canal seguro SSL/TLS»: qué falla, de quién es la culpa y cómo arreglarlo.

1. Introducción

Para cuando un programa, un script o una integración con una API falla al conectar por HTTPS («no se pudo crear un canal seguro SSL/TLS», «la conexión subyacente se cerró», «no poseen un algoritmo común»). Da una respuesta concreta: si el problema es de este equipo, del servidor, del certificado o de la red.

Diagnóstico (solo lee): versiones de Windows, .NET Framework y PowerShell; DNS, puerto y proxy; qué versiones de TLS acepta el servidor desde este equipo, probando TLS 1.3, 1.2, 1.1 y 1.0 una a una; el certificado (emisor, fechas, nombre y cadena de confianza); y la configuración de TLS del equipo (SCHANNEL, .NET Framework 4 y 2 de 64 y 32 bits, WinHTTP). Termina con conclusiones.

Reparación (-Arreglar): activa TLS 1.2 para el cliente, hace que .NET Framework use la criptografía fuerte y las versiones de TLS del sistema y, en Windows anteriores a 10, configura WinHTTP. Guarda antes un .reg con los valores anteriores para deshacer.

Nunca activa SSL, TLS 1.0 ni TLS 1.1 (el script anterior activaba TLS 1.1): son inseguros. Si el servidor solo los admite, el problema es del servidor.

2. Características

🔍

Qué acepta el servidor

TLS 1.3, 1.2, 1.1 y 1.0, uno a uno, con el cifrado negociado.

📜

Certificado

Emisor, fechas, nombre y cadena; avisa si la hora del equipo está mal.

⚙

Configuración del equipo

SCHANNEL, .NET Framework 4 y 2 (64 y 32 bits), WinHTTP y PowerShell.

💡

Conclusiones claras

De quién es el problema y qué hacer.

🔧

Arreglo con vuelta atrás

-Simular, confirmación y .reg con los valores anteriores.

💾

Informe

Todo lo mostrado queda en un .txt en Resultados.

4. Instalación y lanzamiento

Copia la carpeta y ejecuta. Si Windows bloquea el script por no estar firmado: Set-ExecutionPolicy -Scope Process Bypass -Force.

WIN-DiagnosticoTLS\ ├── Diagnosticar-TLS.ps1 ├── Guia_DiagnosticoTLS.html └── Resultados\

5. Cómo se usa

Pasos

Diagnosticar con la URL que falla
Leer las conclusiones
-Arreglar -Simular
-Arreglar y reiniciar
Volver a diagnosticar

Lanza el diagnóstico con la URL que falla (basta el nombre: api.proveedor.com). Sin URL solo revisa la configuración del equipo.

ConclusiónQué hacer
TLS 1.2 desactivado para el cliente-Arreglar y reiniciar.
.NET sin SchUseStrongCrypto / SystemDefaultTlsVersions-Arreglar: las aplicaciones .NET antiguas y Windows PowerShell 5.1 pasan a usar TLS 1.2.
El servidor solo acepta TLS 1.0/1.1Problema del servidor: avisar al proveedor. No activar protocolos obsoletos en el equipo.
Certificado no de confianza o caducadoSi está caducado, es del servidor. Si falla la cadena, actualizar Windows (certificados raíz) o revisar proxy o antivirus que inspeccione HTTPS.
El certificado empieza después de la hora del equipoLa fecha u hora de Windows está mal.
No hay conexión al puertoNo es TLS: firewall, proxy obligatorio o servidor caído.
Los cambios de -Arreglar los leen los programas al arrancar: reinicia el equipo, o al menos el programa afectado. Para deshacer, doble clic en el TLS_vuelta_atras_*.reg de Resultados.

7. Ejemplos

Diagnosticar una API

.\Diagnosticar-TLS.ps1 -Url https://api.proveedor.com/v3/auth/login

Ver qué cambiaría

.\Diagnosticar-TLS.ps1 -Url api.proveedor.com -Arreglar -Simular

Arreglar (como administrador)

.\Diagnosticar-TLS.ps1 -Url api.proveedor.com -Arreglar

Arreglar en muchos equipos sin preguntar

Desde LogMeIn, Intune o GPO.

.\Diagnosticar-TLS.ps1 -Arreglar -SinConfirmar

8. Resolución de problemas

ProblemaCausaSolución
Después de -Arreglar sigue fallandoEl programa no se ha reiniciado o usa su propia configuración.Reiniciar el equipo y volver a diagnosticar; si el servidor solo acepta TLS 1.0/1.1, el problema es suyo.
«no poseen un algoritmo común» en todas las versionesEl servidor exige cifrados o TLS 1.3 que este Windows no tiene.Actualizar Windows o pedir al proveedor que admita TLS 1.2 con cifrados actuales.
Certificado: la cadena no es de confianzaFaltan certificados raíz o intermedios, o un proxy o antivirus inspecciona HTTPS.Windows Update; revisar el emisor que aparece en el informe.
Algo dejó de funcionar tras -ArreglarUn programa muy antiguo dependía de TLS 1.0.Doble clic en el .reg de vuelta atrás y reiniciar; actualizar ese programa.

9. Aviso legal

El diagnóstico solo lee. -Arreglar cambia valores del registro de Windows relacionados con TLS: se guarda copia para deshacer y conviene probarlo antes en un equipo.
Limitaciones conocidas

No cambia la configuración del lado servidor de este equipo (IIS, RDP) ni los cifrados. Las aplicaciones con su propia implementación de TLS (Java, OpenSSL) no usan esta configuración.
