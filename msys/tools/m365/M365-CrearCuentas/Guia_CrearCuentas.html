Crear cuentas en Microsoft 365

Microsoft 365 - Usuarios · Crear-CuentasM365.ps1 · versión 1.0
Alta masiva de usuarios en cualquier tenant a partir de un CSV, con comprobación de tenant y licencias antes de tocar nada.

1. Introducción

Crea de una vez todas las cuentas de un CSV en un tenant de Microsoft 365. Sirve para altas de un cliente nuevo, migraciones de correo (Arsys, IONOS, Google…) o incorporaciones de personal.

Nunca modifica una cuenta que ya existe: si está, solo le asigna la licencia cuando le falta. Antes de crear nada comprueba que estás conectado al tenant correcto, que la sesión tiene los permisos necesarios y cuántas licencias libres hay. Todo queda en un CSV de resultados, contraseñas incluidas, para entregárselas a cada usuario.

Recomendado: ejecutar primero con -Simular, revisar lo que dice y después lanzarlo de verdad.

2. Características

👥

Alta masiva

Todas las cuentas de un CSV en una pasada, con nombre, departamento y puesto.

🔑

Contraseñas seguras

Las del CSV o generadas de 16 caracteres (generador criptográfico, sin caracteres confundibles).

🎫

Licencias

Por defecto o por fila, indicada por su nombre (SkuPartNumber). Avisa si no hay libres suficientes.

🛡

Guarda de tenant

Con -TenantId, si la sesión es de otro tenant se detiene sin tocar nada.

🔄

No pisa nada

Las cuentas que ya existen no se modifican; solo reciben la licencia si les falta.

📧

Alias onmicrosoft

Opcional: espera a que exista el buzón y le añade usuario@<tenant>.onmicrosoft.com (útil para redirecciones durante una migración).

🧪

Modo simulación

-Simular recorre todo y dice qué haría.

📋

Registro

CSV de resultados con fecha, acción, estado, contraseña y detalle del error.

3. Requisitos

RequisitoDetalle
SistemaWindows con PowerShell 5.1 o PowerShell 7
MódulosMicrosoft.Graph (Authentication, Users, Identity.DirectoryManagement). Con -AliasOnMicrosoft, también ExchangeOnlineManagement.
Rol en el tenantAdministrador de usuarios + Administrador de licencias, o Administrador global. Para el alias, Administrador de Exchange.
Permisos de GraphUser.ReadWrite.All, Directory.ReadWrite.All, Organization.Read.All (se piden al conectar).
LicenciasLas que vayas a asignar, con unidades libres.

4. Instalación y lanzamiento

No se instala: se copia la carpeta y se ejecuta. Si faltan los módulos, una sola vez:

Install-Module Microsoft.Graph -Scope CurrentUser
Install-Module ExchangeOnlineManagement -Scope CurrentUser   # solo para -AliasOnMicrosoft

Si Windows no deja ejecutar scripts descargados, en esa ventana de PowerShell:

Set-ExecutionPolicy -Scope Process Bypass -Force

Al lanzarlo pide iniciar sesión en Microsoft 365 (ventana del navegador, con MFA) si no hay una sesión abierta.

M365-CrearCuentas\ ├── Crear-CuentasM365.ps1 el script ├── plantilla_cuentas.csv ejemplo de CSV para copiar ├── Guia_CrearCuentas.html esta guía └── Resultados\ se crea al ejecutar (CSV de cada pasada)

5. Cómo se usa

Pasos

Preparar el CSV
Ejecutar con -Simular
Revisar
Ejecutar de verdad
Entregar las contraseñas
Borrar el CSV de resultados
  1. Prepara el CSV a partir de plantilla_cuentas.csv (Excel vale: lo guarda con ; y el script lo detecta).
  2. Busca el TenantId: Centro de administración de Entra ID → Información general → Id. de inquilino.
  3. Mira el nombre de la licencia: si no sabes cuál es, lanza el script con una licencia inventada; se detendrá y te listará las del tenant con las libres de cada una.
  4. Simula: comprueba tenant, permisos y licencias, y dice qué cuentas crearía o licenciaría.
  5. Ejecuta de verdad: pregunta antes de empezar (S/N). Muestra cada cuenta en verde (hecho), amarillo (ya existía) o rojo (error).
  6. Si usas -AliasOnMicrosoft, al final espera a que Exchange cree los buzones (hasta 20 minutos por defecto) y añade el alias a cada uno.
Una cuenta recién licenciada tarda entre 5 y 20 minutos en tener buzón. Para comprobarlo después, usa la herramienta Verificar cuentas.

Formato del CSV

Separador , o ;, en UTF-8 o ANSI (como lo guarda Excel). Solo UPN es obligatoria; las filas con UPN repetido o mal escrito se avisan y se saltan.

ColumnaQué esEjemplo
UPNobligatorioCuenta (dirección de inicio de sesión). El dominio debe estar verificado en el tenant.maria.lopez@empresa.com
NombreopcionalNombre para mostrar. Si falta, se usa lo que va antes de la @.María López
ContrasenaopcionalContraseña inicial. Si falta, se genera una de 16 caracteres.Verano2026!x

Resultados

En Resultados\CrearCuentas_AAAAMMDD_HHMMSS.csv (separador ;, se abre con Excel): una fila por acción (CREAR, LICENCIA, ALIAS) con Estado OK, YA EXISTIA, YA TENIA, SIMULADO, SIN BUZON o ERROR y el detalle.

Este CSV contiene las contraseñas generadas. Guárdalo en sitio seguro, entrégalas y bórralo. La carpeta Resultados está excluida de Git.

7. Ejemplos

Simulación primero

Comprueba todo y dice qué haría, sin cambiar nada.

.\Crear-CuentasM365.ps1 -Csv .\cuentas.csv -TenantId "00000000-0000-0000-0000-000000000000" -Licencia O365_BUSINESS_PREMIUM -Simular

Alta real con licencia Business Standard

.\Crear-CuentasM365.ps1 -Csv .\cuentas.csv -TenantId "00000000-0000-0000-0000-000000000000" -Licencia O365_BUSINESS_PREMIUM

Migración: alta con alias onmicrosoft

Para redirigir el correo del proveedor antiguo a usuario@tenant.onmicrosoft.com antes de cambiar el MX.

.\Crear-CuentasM365.ps1 -Csv .\cuentas.csv -TenantId "00000000-0000-0000-0000-000000000000" -Licencia O365_BUSINESS_ESSENTIALS -AliasOnMicrosoft

Ver qué licencias tiene el tenant

Con un nombre inventado, se detiene y lista las disponibles con sus unidades libres.

.\Crear-CuentasM365.ps1 -Csv .\cuentas.csv -Licencia VER -Simular

8. Resolución de problemas

ProblemaCausaSolución
«Falta el módulo Microsoft.Graph»No está instalado.Install-Module Microsoft.Graph -Scope CurrentUser
«Tenant incorrecto»Había una sesión abierta de otro cliente.Disconnect-MgGraph y volver a lanzarlo; al conectar, entra con la cuenta del tenant correcto.
«La sesión no tiene estos permisos»Se aceptó el inicio de sesión sin consentir los permisos, o la cuenta no puede darlos.Disconnect-MgGraph y repetir con una cuenta con rol de administrador; aceptar los permisos que pide.
«La licencia … no existe en este tenant»Nombre mal escrito o el tenant no tiene esa licencia.Usar uno de los nombres que lista el propio mensaje.
Error al crear: dominio no válidoEl dominio del UPN no está verificado en el tenant.Verificar el dominio en el Centro de administración o usar el .onmicrosoft.com.
Error al crear: la contraseña no cumple la directivaLa contraseña del CSV es corta o simple.Dejar la columna vacía para que la genere, o poner una más larga y variada.
Error de licencia «License assignment failed»Sin unidades libres o falta la ubicación de uso.Comprar o liberar licencias; el script fija la ubicación, revisar si el error persiste.
Alias: «SIN BUZON»Exchange aún no ha creado el buzón.Esperar y relanzar con el mismo CSV y -AliasOnMicrosoft: las cuentas ya creadas se saltan.

9. Aviso legal

Esta herramienta hace cambios reales en el sistema o el tenant donde se ejecuta. Úsala primero con -Simular cuando lo tenga, con una cuenta con los permisos justos y sabiendo qué va a cambiar. El autor no se hace responsable de un uso indebido ni de los daños derivados de su ejecución.
Limitaciones conocidas

No crea grupos ni buzones compartidos (hay herramientas aparte). No asigna roles de administrador. Las licencias se asignan completas (sin desactivar servicios sueltos). El alias se pone solo a cuentas con buzón; si Exchange tarda más de lo indicado en -MinutosEsperaBuzon, hay que relanzarlo.
